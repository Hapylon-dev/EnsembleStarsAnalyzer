# ensemble-stars-analyzer

**あんさんぶるスターズ！！Music タップタイミング解析Webアプリ**

**Version 3.3.3-dev（2026年11月11日）**

**あんさんぶるスターズ！！Musicのリザルト画像を解析する「タップタイミング解析Webアプリ」です。付属機能として、独立したパチンコ風ミニゲーム「OVERALL PACHINKO」を収録しています。**

リザルト画像をアップロードし、楽曲情報を入力するだけで、判定分布の推定、Precision、Balance、Overall Score、Rank、ランキングなどを確認できます。

> ⚠️ 本ツールは非公式ファンメイドツールです。  
> Happy Elements株式会社とは関係ありません。

スマートフォン・タブレット・PCのブラウザから利用できます。

### STEP 2：起動するまで待つ

`This will take just a sec! Your app is waking up!` と表示された場合は、アプリが起動するまでそのままお待ちください。

## 🎰 OVERALL PACHINKO（ミニゲーム）

詳細な操作・ルール・スペック・保留信頼度・RANKボーダーは、OVERALL PACHINKO画面内の「はじめての方へ｜完全ガイド」（全8章）から確認できます。単独のマニュアルは `docs/OVERALL_PACHINKO_BEGINNER_MANUAL.md` にあります。

トップのタブから、リザルト画像を用意しなくても遊べる「OVERALL PACHINKO」を利用できます。

- 通常モード：固定1,799件のOVERALLから重複ありで1件を抽選します。
- 通常時演出：STANDARD／FORESHADOW／QUICKを選択でき、保留入賞・先読み・チャンス・リーチ・最終発展を段階的に表示します。演出段階は演出専用乱数で決まり、抽選結果・確率・出玉には影響しません。
- 小数点以下3桁が同じ数字の場合に初当たりとなり、RUSHへ突入します。
- RUSH：大当たり確率1/73。ST116回転＋残保留最大4個（合計最大120回）。ST本体終了後は新しい保留を追加できず、貯まっている残保留だけを消化します。当たりでST116回転に再セットします。
- RUSH演出モード：STANDARD／SHADOW VISITOR／IMPACT／ONE PUSHを選択でき、RUSH中も変更できます。
- 連チャン数に応じて画面演出が段階的に強化されます。演出は抽選結果確定後の表示であり、抽選確率・出玉には影響しません。
- 結果画面：獲得NOTES・COMBO・払出分布を確認し、結果画像の保存やX共有ができます。

このミニゲームはタップタイミング解析とは独立しています。ゲーム内の公式機能・確率・報酬を再現するものではありません。

## 📌 解析値について

タップタイミング解析は、対象条件を満たすALL AMAZING相当のリザルト画像を対象とします。棒グラフの高さから判定数を推定するため、表示値は実数ではなく参考値です。既存のスコア計算式は維持しています。

# 🎮 1．解析できるリザルト画像

解析する前に、使用するスクリーンショットが条件を満たしているか確認してください。

## 対応しているリザルト

現在の対象は、**新ライブUI（2025年4月29日以降）のライブリザルト画面**です。

対応しているライブは以下です。

- ライブチャレンジ
- ノーマルライブ
- あんさんぶるライブ
- ソロライブ

ただし、ライブの種類によって対象となるリザルト表示が異なります。

### ライブチャレンジ

リザルト画面に、

**ALL AMAZING（100.000%）**

と表示されているリザルトが対象です。

### ノーマルライブ・あんさんぶるライブ・ソロライブ

リザルト画面に、

**PERFECT COMBO**

と表示されているリザルトが対象です。

これらのライブでは画面上に「AMAZING」が最高判定として表示されないため、タップタイミング棒グラフから内部的なALL AMAZING相当かを判断します。

---

## 画像の条件

次の条件をすべて満たす画像を使用してください。

- ゲーム内のライブリザルト画面のスクリーンショット
- 新ライブUI（2025年4月29日以降）
- 編集・加工していない画像
- 十分な解像度がある画像
- タップタイミング棒グラフがはっきり表示されている
- 棒グラフが中央1本＋左右各1本の合計3本以内に収まっている
- ALL AMAZING相当の結果
- MISSがない
- 総ノーツ数と最高判定数が一致している

### 棒グラフを見るときのポイント

タップタイミング棒グラフは、**中央に近いほど正確なタイミング**を表します。

対象となるAMAZING判定の棒は、

- 中央
- 中央の左
- 中央の右

の最大3本です。

棒グラフが途中で切れている、ぼやけている、加工されている画像では、正しく解析できない場合があります。

### MISSについて

MISSはタップタイミング棒グラフには表示されません。

そのため、リザルト画面を見て、

**総ノーツ数と最高判定数が一致していること**

も確認してください。

> ⚠️ 条件を満たさない画像は解析対象外です。  
> 条件を満たしていても、画像の状態によって正しく解析できない場合があります。

# 📷 2．リザルト画像をアップロードする

Webアプリを開くと、リザルト画像をアップロードする欄があります。

対応している画像形式は、

- PNG
- JPG
- JPEG
- WebP

です。

画像をアップロードすると、入力画面の下に**「解析対象となるリザルト画像」**としてアップロードした画像が表示されます。

アップロードした画像を見て、正しいリザルト画像になっていることを確認してください。

### ファイルサイズ

アップロードできる画像は**最大20MB**です。

20MBを超える画像は解析できません。

# 🎼 3．楽曲情報を入力する

画像をアップロードしたら、画像に表示されている楽曲情報を入力します。

## 楽曲名

ゲームのリザルト画面に表示されている曲名を入力してください。

最大**50文字**まで入力できます。

以下から選択します。

- Easy

- Hard

- Special

リザルト画面と同じ難易度を選択してください。

---

選択した難易度に応じて、入力できるレベルが変わります。

| Easy | 5～10 |
| Normal | 11～17 |
| Hard | 17～26 |
| Expert | 23、24、25、26、26+、27、27+、28、28+、29、29+、30、30+ |
| Special | 26、26+、27、27+、28、28+、29、29+、30、30+、31、31+、♪1～♪6 |

> ※ Expert・Specialでは「+」付きのレベルや「♪」表記のレベルも選択できます。

---

## 🔢 総ノーツ数

**ゲームのリザルト画面に表示されている総ノーツ数を、そのまま入力してください。**

入力範囲は、

**60～1800**

です。

総ノーツ数は非常に重要です。

本ツールでは、棒グラフから判定分布を推定したあと、その割合を入力された総ノーツ数に換算します。

そのため、総ノーツ数を間違えると、推定される判定数やAchievementなどの結果も正しくならない場合があります。

> ⚠️ 総ノーツ数は必ずリザルト画面の表示を確認して入力してください。

# ▶️ 4．解析を開始する

入力が終わったら、

**「▶ 解析開始」**

を押してください。

解析では、

1. リザルト画像を読み込む
2. タップタイミング棒グラフを解析する
3. 判定分布を推定する
4. 各種評価を計算する
5. リザルトカードを生成する
6. ランキングを計算する

という処理が行われます。

解析が完了すると、

**「✅ 解析が正常に完了しました。」**

と表示され、結果を確認できます。

# 🏅 11．ランキング称号

ランキング順位の**上位率（%）**に応じて、本ツール独自のランキング称号が決まります。

**上位率は数値が小さいほど上位**です。  
たとえば「上位10%」は、ランキング全体の上位10%以内を意味します。

現在の称号は以下の12種類です。

| 絵文字 | ランキング称号 | ボーダー（上位率） |
|:---:|---|---:|
| 🌈 | レインボーランカー | **上位5%以内** |
| 💎 | ダイヤモンドランカー | **上位10%以内** |
| 🤍 | プラチナランカー | **上位15%以内** |
| 💛 | ゴールドランカー | **上位20%以内** |
| 🩶 | シルバーランカー | **上位25%以内** |
| 🤎 | ブロンズランカー | **上位30%以内** |
| 🟣 | パープルランカー | **上位50%以内** |
| 🔴 | レッドランカー | **上位60%以内** |
| 🟠 | オレンジランカー | **上位70%以内** |
| 🟢 | グリーンランカー | **上位80%以内** |
| 🔵 | ブルーランカー | **上位90%以内** |
| ⚪ | ホワイトランカー | **上位100%以内** |

### 称号の決まり方

上位率を上位から順に判定し、最初に該当するボーダーの称号が表示されます。

たとえば、

- **上位4.0%** → 🌈 レインボーランカー
- **上位7.5%** → 💎 ダイヤモンドランカー
- **上位14.0%** → 🤍 プラチナランカー
- **上位18.0%** → 💛 ゴールドランカー
- **上位24.0%** → 🩶 シルバーランカー
- **上位29.0%** → 🤎 ブロンズランカー
- **上位45.0%** → 🟣 パープルランカー
- **上位55.0%** → 🔴 レッドランカー
- **上位65.0%** → 🟠 オレンジランカー
- **上位75.0%** → 🟢 グリーンランカー
- **上位85.0%** → 🔵 ブルーランカー
- **上位95.0%** → ⚪ ホワイトランカー

という判定になります。

# 🎰 OVERALL PACHINKO 詳細マニュアル（3.3.0-dev）

OVERALL PACHINKOは、タップタイミング解析とは独立したミニゲームです。解析用スコア計算式・固定ランキング基準データは変更しません。

## 1. 通常時・初当たり

- 固定1,799件のOVERALLデータから、重複ありで1件ずつ抽選します。
- 小数点以下3桁が同じ数字なら通常初当たりです。
- 通常初当たり確率は約1/34.6です。
- 通常初当たり後は必ずRUSHへ突入します。
- 150回転連続で初当たりがない場合、150回転目に遊タイムが発動します。

| 通常初当たり図柄 | 出玉 | 件数 | 振り分け |
|---|---:|---:|---:|
| `000` | 1,500 NOTES | 29 | 29/52 |
| `222 / 444 / 666 / 888` | 300 NOTES | 14 | 14/52 |
| `111 / 333 / 555 / 999` | 3,000 NOTES | 8 | 8/52 |
| `777` | 4,500 NOTES | 1 | 1/52 |

## 2. 遊タイム

- 発動条件：通常時に150回転連続で初当たりがないこと。
- 150回転目の抽選がハズレの場合に発動します。
- 発動時は6,000 NOTESを獲得し、RUSHへ突入します。
- 表示区分は `PITY TIME`、初当たりOVERALLは `--.---` です。
- 理論発動確率は `(1 - 1/34.6)^150` = 約1.2288%です。
- 通常時の大当たり確率約1/34.6と遊タイム発動確率は合算しません。

## 3. RUSH

- 大当たり確率：1/73
- ST本体：116回転
- ST終了時の残保留：最大4個（最大合計120回）
- ST本体終了後は保留追加不可。すでに貯まっている残保留だけを消化
- 残保留を消化し終えると終了
- ST本体のみの継続期待度：約79.81%
- 残保留4個を含む最大120回の継続期待度：約80.89%

| RUSH大当たり出玉 | 振り分け |
|---:|---:|
| 300 NOTES | 20% |
| 1,500 NOTES | 50% |
| 3,000 NOTES | 15% |
| 4,500 NOTES | 10% |
| 6,000 NOTES | 5% |
| **合計** | **100%** |

RUSH大当たり1回あたりの平均出玉は2,010 NOTESです。ルーレットは演出であり、出玉は演出開始前に決定されます。

保留は最大5個、HOLD長押し中は0.5秒ごとに追加します。STは保留追加時ではなく消費時に減少します。大当たり中は保留処理を停止し、当たり時に未消費の保留4個は当否・色を保持して次のRUSHへ持ち越します。

## 4. 理論期待出玉

| 指標 | 理論値 |
|---|---:|
| 通常初当たり平均出玉 | 約1,465.38 NOTES |
| 遊タイム込み通常時出玉期待値 | 約1,521.11 NOTES |
| RUSH大当たり回数期待値 | 約4.23412回 |
| RUSH獲得期待出玉 | 約8,510.58 NOTES |
| 通常時開始からの総獲得期待出玉 | 約10,031.69 NOTES |

「RUSH獲得期待出玉」と「通常時開始からの総獲得期待出玉」は異なる指標です。

## 5. 100万件シミュレーション

アプリ内に、1,000,000件の試行件数、遊タイム発動件数・割合、通常初当たり件数、RANK別件数・割合、ヒストグラムを表示します。理論値とシミュレーション実測値は別々に表示します。試行単位は「件」です。

再現条件・個別試行CSV.gz・集計JSON・RANKヒストグラムCSVは `output/simulation/` に保存します。標準乱数シードは20261111です。

## 8. Supabaseランキング設定

詳しい画面操作は `SUPABASE_SETUP_3.3.0-dev.md` を参照してください。

新規Supabaseプロジェクトでは、SQL Editorで `supabase/pachinko_schema.sql` の内容を実行します。テーブル、RLSポリシー、ランキング順位を返すRPC関数を作成します。

Streamlit Secretsには次の値を登録します。

```toml
SUPABASE_URL = "https://YOUR_PROJECT.supabase.co"
SUPABASE_PUBLISHABLE_KEY = "sb_publishable_..."
```

旧形式の `SUPABASE_ANON_KEY` も互換のため読み込みます。新しい `sb_publishable_...` キーは `apikey` ヘッダーだけに設定し、Bearer JWTとしては送信しません。旧形式のanon JWTではBearerヘッダーも使用します。`service_role` / `sb_secret` キーは絶対にブラウザへ公開しないでください。アプリ側でも新形式の `sb_secret_` と旧形式JWTの `service_role` を検出してランキング接続を停止します。

現在の公開ランキング方式は、匿名ユーザーに結果のINSERTとSELECTを許可します。これは共有ランキングを簡単に有効化するための方式であり、投稿者本人の正当性やスコアの正しさをサーバーで証明するものではありません。不正投稿防止を強化する場合は、Supabase Edge Function等でサーバー側検証を行う設計へ移行してください。
